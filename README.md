# 设施土壤微生态失衡指数（MDI）计算平台

设施土壤微生态失衡指数（MDI）计算平台的**纯前端**版本，部署到 GitHub Pages；云端「登录 / 保存 / 读取 / 删除」功能由 [Supabase](https://supabase.com)（免费额度）提供。

**在线访问**：<https://syau-soil.github.io/mdi-platform/>
**仓库地址**：<https://github.com/syau-soil/mdi-platform>

# 第一部分 · 平台说明（指标与计算）

## 1. 平台定位

本平台用于设施土壤微生态失衡水平的**定量化分等定级**：把 4 个维度共 12 项易获取指标的实测值，统一换算为 0–1 的标准化分值，按两层权重合成「综合健康度 H」，再取 **MDI = 1 − H** 作为失衡指数，按阈值划分**健康 / 轻度失衡 / 中度失衡 / 重度失衡**四个等级。

平台为纯前端网页：全部计算在浏览器内完成，**默认不上传任何数据**；只有用户登录并主动点击「保存到云端」时，数据才写入其个人云端账户（按账户隔离）。无网络时计算与导出功能照常可用。

## 2. 评价方法框架

评价流程采用「指标筛选 → 标准化 → 赋权 → 合成指数 → 分等」五步法：

```
指标实测值 x
   │  ① 标准化（按指标属性选用效益型 / 成本型 / 最优区间型）
   ▼
指标标准分 S ∈ [0, 1]
   │  ② 第二层权重：维度内指标加权
   ▼
维度分 D_k（生境稳定性 / 微生物稳定性 / 养分循环功能 / 生态防御与抗逆）
   │  ③ 第一层权重：四维加权
   ▼
综合健康度 H = Σ w_k · D_k ∈ [0, 1]
   │  ④ 取失衡指数并阈值分等
   ▼
MDI = 1 − H：健康 ≤ 0.25 / 轻度失衡 0.25–0.50 / 中度失衡 0.50–0.75 / 重度失衡 > 0.75
```

**关于权重方法的说明**：平台当前采用**可编辑权重的等权默认方案**（两层均默认等权，用户可改为分数或小数），并未内置层次分析法（AHP）的判断矩阵与一致性检验。如需按 AHP 表达专家判断，可组织专家对各层两两比较，把求得的结构权重直接填入平台的权重输入框（平台自动归一化，等价于 AHP 求得的权重向量）。

## 3. 指标标准化方法

### 3.1 效益型（越大越好）

MWD、MBC、B/F、可培养有益菌数量、NAG 酶活性、CO₂ 排放降低幅度、拮抗活性有益菌数量、根际抑病率。

```
S = (x − 劣) / (优 − 劣)        结果截断到 [0, 1]
```

- x ≤ 劣 → 0 分（达到失衡端参照值）
- x ≥ 优 → 1 分（达到健康端参照值）

### 3.2 成本型（越小越好）

EC、土壤矿质氮（硝态氮+铵态氮）、尖孢镰刀菌数量。

```
S = (劣 − x) / (劣 − 优)        结果截断到 [0, 1]
```

- x ≥ 劣 → 0 分；x ≤ 优 → 1 分

### 3.3 最优区间型（存在最适区间）

pH。

```
             x − x_min                  （x < opt_L，低于最优下限）
S = ⎧   ─────────────
    ⎪    opt_L − x_min
    ⎨
    ⎪    1                             （opt_L ≤ x ≤ opt_H，最优区间内）
    ⎩
    ⎪    x_max − x                     （x > opt_H，高于最优上限）
         ─────────────
         x_max − opt_H
```

即：落在最优区间 [opt_L, opt_H] 内记满分 1；区间外按「到区间边界的距离 / 边界到失效端点的距离」线性衰减，到达最小值或最大值时记 0 分。区间型指标共 4 个参数：最优下限、最优上限、最小值、最大值。

### 3.4 缺值处理

某指标缺测时按 **0 分**计入并在结果中标注「⚠缺 n 项」，避免整行样本被剔除；建议实测补齐后重算。

## 4. 指标体系与默认阈值

共 4 维 12 指标。「优」= 健康端参照值，「劣」= 失衡端参照值。下表数值为**平台代码内置默认值**（逐项与 `_c.js` 核对），所有阈值均可在界面中修改，鼓励以项目实测的连作对照（CK）与调控处理（T）数据本地化校准。

### 4.1 生境稳定性

| 指标 | 类型 | 劣（失衡端） | 优（健康端） |
|---|---|---|---|
| 土壤团聚体平均重量直径 MWD (mm) | 效益型 | 0.33 | 0.55 |
| 土壤 pH | 区间型 | 最优 6.0–7.0；最小 5.3 / 最大 8.0 | — |
| 土壤电导率 EC (mS·cm⁻¹) | 成本型 | 优 0.30 | 劣 0.70 |

### 4.2 微生物稳定性

| 指标 | 类型 | 劣 | 优 |
|---|---|---|---|
| 微生物量碳 MBC (mg·kg⁻¹) | 效益型 | 150 | 290 |
| 细菌/真菌数量比 B/F | 效益型 | 1.0×10³ | 5.0×10³ |
| 可培养有益菌数量 (CFU·g⁻¹) | 效益型 | 1.0×10⁵ | 1.0×10⁷ |

### 4.3 养分循环功能

| 指标 | 类型 | 劣 | 优 |
|---|---|---|---|
| 土壤矿质氮（硝态氮+铵态氮）(mg·kg⁻¹) | 成本型 | 优 97.1 | 劣 300 |
| 关键酶活性（N-乙酰-β-D-氨基葡萄糖苷酶 NAG, nmol·g⁻¹·h⁻¹） | 效益型 | 60.7 | 135.8 |
| CO₂ 排放降低幅度 (%) | 效益型 | 0 | 12 |

### 4.4 生态防御与抗逆

| 指标 | 类型 | 劣 | 优 |
|---|---|---|---|
| 尖孢镰刀菌数量 (CFU·g⁻¹) | 成本型 | 优 1.0×10³ | 劣 1.0×10⁵ |
| 拮抗活性有益菌数量 (CFU·g⁻¹) | 效益型 | 1.0×10⁴ | 1.0×10⁶ |
| 根际抑病率 (%) | 效益型 | 0 | 96 |

**口径提示（两条，重要）**：

1. B/F、可培养有益菌、拮抗活性有益菌的默认阈值均按**平板计数（CFU·g⁻¹）口径**设定。若实际数据来自高通量测序相对丰度或 qPCR，数量级完全不同，必须同步改阈值（或换算口径），否则分值失真。
2. 本平台阈值与 MEHI（微生态健康指数）计算平台**并不完全相同**——例如矿质氮劣端本平台为 300（MEHI 为 117.0）、pH 最小值本平台为 5.3（MEHI 为 4.5），且本平台养分循环维度用 **NAG 酶活性**替代了 MEHI 的 DON。两套平台结果不可直接互比，引用时注意区分口径。

## 5. 权重体系（两层）

1. **第一层 · 维度权重**：4 个维度（生境稳定性、微生物稳定性、养分循环功能、生态防御与抗逆）各 1 个权重，决定各维度在 H 中的相对重要性。
2. **第二层 · 维度内指标权重**：每个维度内部 3 个指标的权重，决定维度分的构成。

- 权重可填**分数（如 1、2、3）或小数（如 0.25）**；
- 每层**分别自动归一化**（w_i / Σw），填相等值即为等权；
- 界面实时显示每个权重归一化后的百分比，便于核对；
- 「恢复默认阈值与权重」一键回到出厂状态。

## 6. 综合指数与分等

```
维度分  D_k = Σ (第二层归一化权重 × 指标标准分 S)     （越大表示状态越好）
H           = Σ (第一层归一化权重 × D_k)
MDI         = 1 − H                                   （越小越健康）
```

| 等级 | MDI 区间 | 管理含义 |
|---|---|---|
| 健康 | ≤ 0.25 | 微生态功能良好，维持性管理 |
| 轻度失衡 | 0.25 – 0.50 | 出现早期退化信号，针对性调控（补碳、控氮、补菌） |
| 中度失衡 | 0.50 – 0.75 | 功能明显退化，需系统性调控（结构改良 + 生物修复） |
| 重度失衡 | > 0.75 | 连作障碍风险高，需强干预（RSD/生物有机肥/轮作倒茬） |

分等阈值 0.25 / 0.50 / 0.75 与平台内置一致；如需改用其他分级方案，在导出结果后按 MDI 列重新划档即可。

## 7. 数据格式与导入

**列顺序（13 列）**：样本名、MWD、pH、EC、MBC、B/F、可培养有益菌数量、矿质氮、NAG 酶活性、CO₂ 降低幅度、镰刀菌数量、拮抗活性有益菌数量、抑病率（与界面表格列一一对应，导入表头含「样本」「MWD」等字段名时自动识别跳过）。

- 支持**逗号 / Tab / 分号 / 中文逗号 / 空格**分隔；
- 大数可用科学计数法（如 `1.3e+07`），与普通数字等价；
- 电脑端：Excel 复制 → 粘贴框 → 「解析粘贴」；或直接「导入 CSV」；
- 手机端：逐行「＋ 添加样本行」，或先「下载 CSV 模板（20 条示例）」参照格式；
- 「填入示例数据」为 3 条内置演示样本，**按默认等权计算 MDI 分别为 0.159（健康）/ 0.521（中度失衡）/ 0.844（重度失衡）**，可用于快速核对算法；
- 「下载 CSV 模板」为 20 条模拟样本，按默认等权计算分布为**健康 7 条 / 轻度失衡 1 条 / 中度失衡 6 条 / 重度失衡 6 条**（MDI 0.095–0.899）。

## 8. 操作与计算流程

1. 打开平台地址（或本地双击 `index.html`）；
2. 导入数据（模板 CSV / Excel 粘贴 / 手工添加）；
3. 核对第 2 节两层权重与阈值（可改，可恢复默认）；
4. 点「▶ 运行计算」→ 得到维度分、MDI、等级及各指标过程分 S（0–1）；
5. 「导出结果 CSV」留存过程数据与结果（含各维度归一化权重百分比）；
6. （可选）登录后「保存到云端」，换设备可「读取云端记录」并一键「载入」阈值+数据复算。

## 9. 局限性与使用注意

1. 默认阈值为**平台内置参照值**，**正式评价前应以项目实测 CK/T 数据校准**，尤其 B/F 与两类可培养菌计数受培养基、培养条件影响大；
2. pH 最优区间默认 6.0–7.0（最小 5.3 / 最大 8.0），可按作物与产区调整；
3. EC 劣端默认 0.70 mS·cm⁻¹，不同产区盐渍化临界值不同（约 0.60–0.70），使用前请按产区核对；
4. 矿质氮劣端默认 300 mg·kg⁻¹（MEHI 平台为 117.0），本平台取值偏宽松，校准前请注意；
5. 缺值按 0 分计并标注，样本缺项多时等级偏保守（MDI 偏大）；
6. 本平台输出为**相对等级**，用于样本地块间比较与调控效果评估，不宜直接作为绝对诊断结论；
7. CO₂ 排放降低(%) 需与对照（CK 或处理前）对比计算后填入。

# 第二部分 · 部署指南（GitHub Pages + Supabase）

## 10. 文件说明

| 文件 | 作用 |
|---|---|
| `index.html` | 页面结构 + 样式，通过 `<script src="_c.js">` 加载逻辑 |
| `_c.js` | 全部业务逻辑（指标归一化、加权、计算、导出、Supabase 云端存取） |
| `.nojekyll` | **必须保留**：关闭 GitHub Pages 的 Jekyll，否则以下划线开头的 `_c.js` 不会被发布 |
| `README.md` | 本文件 |

## 11. 创建 GitHub 账号

1. 打开 <https://github.com>，点 **Sign up**（右上角）。
2. 填用户名、邮箱、密码；完成人机验证；验证邮箱（GitHub 会发一封确认邮件，点里面的链接）。
3. 注册完成后登录即可。**不需要付费**，免费账号就能用 GitHub Pages。

## 12. 新建仓库

1. 登录后点右上角 **+ → New repository**。
2. Repository name 随意，例如 `mdi-platform`（会决定网址，建议小写、用连字符）。
3. 可见性选 **Public**（GitHub Pages 免费版要求公开仓库）。
4. **不要**勾选 "Add a README file" / ".gitignore" / "license" —— 我们要把本目录原样推上去，避免冲突。
5. 点 **Create repository**，进入空仓库页面。

## 13. 创建 Supabase 项目（云端保存的后端）

1. 打开 <https://supabase.com>，用 GitHub 账号登录最方便，点 **Start your project**。
2. **New project**：填名字（如 `mdi`）、设置数据库密码（记下来）、选区域（离你近的，如 Singapore）。
3. 创建后等待几十秒。进入项目，左侧菜单 **Project Settings → API**：
   - 复制 **Project URL**（形如 `https://xxxx.supabase.co`）
   - 复制 **anon / public key**（一长串 `eyJ...`）
4. 左侧 **SQL Editor → New query**，把下面整段 SQL 粘贴进去执行（建表 + 开启行级安全）：

```sql
create table if not exists mdi_records (
  id bigint generated always as identity primary key,
  record_name text,
  data jsonb,
  created_at timestamptz default now(),
  user_id uuid not null default auth.uid() references auth.users
);

alter table mdi_records enable row level security;

create policy "owner_select" on mdi_records for select using (auth.uid() = user_id);
create policy "owner_insert" on mdi_records for insert with check (auth.uid() = user_id);
create policy "owner_delete" on mdi_records for delete using (auth.uid() = user_id);
```

> 这段 RLS 策略保证**每个用户只能看到自己保存的记录**。一定执行，否则数据会互相暴露。

5. （可选但推荐）左侧 **Authentication → Providers → Email**，打开 **Email OTP**（这样"获取验证码"会发 6 位数字码，可在页面输入）。不打开则用"魔法链接"登录（点邮件里的链接直接登录）。

## 14. 填入 Supabase 配置

打开本仓库的 `_c.js`，把最上面的 `CLOUD_CONFIG` 改成你的真实值：

```js
const CLOUD_CONFIG = {
  endpoint: "https://你的PROJECT-REF.supabase.co",   // 第 13 步拿到的 Project URL
  publishableKey: "你的ANON-KEY"                     // 第 13 步拿到的 anon key
};
```

如果保持默认（`YOUR-...` 占位符），平台仍可正常使用**计算和 CSV 导出**，只是云端保存不可用。

## 15. 启用 GitHub Pages

1. 仓库页 **Settings → Pages**（左侧栏最下方）。
2. **Source**：选 **Deploy from a branch**；Branch 选 **main**，目录选 **/ (root)**；点 **Save**。
3. 等 1–2 分钟，页面顶部会出现 `https://你的用户名.github.io/mdi-platform/` 这样的地址，就是你的线上平台。

## 16. 把代码推到 GitHub

在**本目录**（`MDI平台-github`）打开终端，执行：

```bash
git init
git add -A
git commit -m "MDI platform: GitHub Pages + Supabase"
git branch -M main
git remote add origin https://github.com/你的用户名/mdi-platform.git
git push -u origin main
```

`git push` 时会要求登录 GitHub：用 **GitHub 账号 + 密码**现已不支持，请改用 **Personal Access Token（PAT）** 当密码。生成 PAT：GitHub 右上角头像 → **Settings → Developer settings → Personal access tokens → Tokens (classic) → Generate new token**，勾 `repo` 权限，复制保存。

> 如果不想自己敲命令，可以把**仓库地址**和**一个具有 repo 权限的 PAT**发给开发者，直接推上去。

## 17. 验证

1. 打开你的 GitHub Pages 地址。
2. 点"获取验证码"用邮箱注册/登录（或密码登录）。
3. 填入/导入数据 → 点"▶ 运行计算"。
4. 点"保存到云端" → 给记录命名。
5. 刷新页面 → "读取云端记录"，确认能载入刚才保存的数据。

## 18. 云服务与数据隐私

- **anon key 可公开**，但必须配合第 13 步的 RLS 策略；没开 RLS 千万别公开仓库里的任何密钥以外的数据。
- **`service_role` 密钥绝不可出现在前端代码里**（本仓库只用到 anon key）。
- 云端保存为**显式选择行为**：邮箱登录（密码 / 验证码）后手动点击才写入；云端记录按账户隔离，每条记录保存完整的数据 + 阈值 + 权重 + 结果，可跨设备载入复算。
- 本版的"忘记密码"走 Supabase **邮件链接**流程：点"忘记密码"→ 收邮件 → 点链接回到页面（自动进入恢复会话）→ 填新密码提交。验证码框在 Supabase 模式下留空即可。
- 邮箱验证码登录需要站点运行在 **https** 下（GitHub Pages 满足）。
- Web 端仅支持邮箱登录，不支持手机号 / 微信登录。

## 19. 注意事项（重要）

- 本仓库代码已按 **Supabase JS v2** 接口改写，并已用真实 Supabase 项目验证：建表 SQL、RLS 策略、anon key 经 REST 探测均可用。
- **邮件发送通道尚待完善**：Supabase 默认内置发信受限（基本只发项目成员邮箱），且 Email OTP 默认未开启。如果注册/收验证码时报 `Error sending confirmation email`，需要：① 配自定义 SMTP（推荐 163：`smtp.163.com:465`，密码填**授权码**非登录密码）；② Authentication → Providers → Email 打开 **Email OTP**。临时测试可先在 Authentication → Users 里手动 Add user（勾 Auto Confirm）再用密码登录。
- 修改 `_c.js` 或 `index.html` 后重新推送即可更新线上版本（GitHub Pages 自动重新部署，约 1 分钟生效）。
